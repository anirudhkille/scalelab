# Decisions

One line each: decision, and why.

- **bun instead of pnpm** — the plan says pnpm, but the user chose bun and pnpm is not installed in this environment.
- **Node 26** — user requirement; `engines.node` is `>=26`.
- **oxlint instead of ESLint** — user requirement. oxlint cannot express `consistent-type-definitions` or feature import boundaries, so `scripts/check-conventions.mjs` enforces those rules alongside oxlint.
- **Vitest instead of an unspecified test runner** — user requirement; jsdom + Testing Library are configured.
- **React Router v8** — the plan allows React Router or TanStack; React Router is already installed and wired.
- **shadcn Base UI, preset `nova` / style `base-nova`** — matches the plan's Base UI requirement.
- **No `number-field` component** — it is not in the Base UI registry (CLI returned 404); the plan's fallback is `Input` plus a custom stepper when parameter forms arrive in M3.
- **Inter + JetBrains Mono** — chosen for UI/mono typography. The unused Geist font and `next-themes` packages were removed during M1.
- **Theme tokens live in `src/index.css`** — user requested that `theme.css` be folded into the Tailwind entry instead of a separate `shared/styles/theme.css`.
- **Lowercase kebab-case filenames** — user requirement. React component identifiers remain PascalCase.
- **`LoadStage` is defined in `features/challenges/schema.ts`** — challenges are to the left of simulation in the dependency graph, and simulation may import challenges. This avoids a forbidden challenges → simulation import.
- **`cn` from the official `cn` package** — generated by current shadcn/Base UI registry; `src/shared/lib/utils.ts` re-exports it for project code.
- **Challenges include an optional `referenceSolution`** — needed for the gated sample solution and engine tuning, even though the §5.2 schema snippet omits it.
- **`referenceSolution`/`starterArchitecture` are optional** — authored challenges can ship without either, and both are validated by `architectureSchema` when present.
- **Route screens live in `features/<name>/pages/`** — user requirement. `src/routes` is removed; the router imports page components from feature public APIs. The not-found fallback stays in `app/pages/` because it is app-level, not a domain feature.
- **M1 placeholder behaviors for unmodeled kinds** — M1 had to keep every catalog kind runnable. Gateway and rate limiter enforced capacity; cache, database, queue, worker, CDN, DNS, and object storage stayed pass-through with representative latency until M2. Only DNS, gateway, rate limiter, and object storage remain pass-through.
- **M2 data components are deterministic approximations** — cache uses `(memory/workingSet)^0.6 * 0.98` with a 20s linear warm-up; CDN absorbs only static hits; DB read/write capacities share one equivalent queue; sharding uses a hot-shard multiplier; queue/worker backpressure uses the generic queue. These are teaching models, not benchmarks.
- **Storage exhaustion is checked per DB node** — the runner passes the IDs of databases whose `dataSizeGb` exceeds `shards * storagePerShardGb` into failure detection. This keeps the failure reason and root-cause node in the normal breach pipeline instead of special-casing a pre-run error.
- **Undersized cache wins root-cause attribution over the database symptom** — when a database is saturated and a cache's steady hit ratio is below 0.5, the cache is reported as the root cause. This makes the failure report actionable instead of blaming the component that merely absorbed the misses.
- **Diagnosis rules are data plus predicates** — `features/diagnosis/rules/catalog.ts` holds 16 ordered templates with metadata and `matches` functions. `diagnoseFailure` selects the first match and returns evidence; the M5 report modal can render it without duplicating rule logic.
- **Diagnosis is a separate feature, not part of simulation** — it imports architecture/challenges/simulation public APIs and follows the dependency direction. The engine stays focused on mechanics; explanation copy and rule prioritization can evolve independently.
- **Terminal nodes consume traffic** — a node with no outgoing edges is a sink, not a drop. This lets app servers and other terminal components pass a run instead of reporting unroutable traffic as errors.
- **Timeout is a failure reason** — `maxSimulatedSec` protects against non-terminal runs. The plan's four failure reasons remain, with `timeout` added as an engine safety outcome and documented in `ENGINE.md`.
- **Route pages are lazy-loaded** — every page route uses `React.lazy` behind an app-level `<Suspense>` fallback, and Vite splits React, React Router, Base UI, and icons into vendor chunks. This keeps the initial bundle smaller as the workspace grows.
- **oxlint covers correctness/performance; custom script covers architecture** — `.oxlintrc.json` enables React, react-perf, import, jsx-a11y, vitest, promise, and unicorn rules plus correctness/suspicious/perf categories. Rules oxlint cannot express (type aliases, import boundaries, engine purity) stay in `scripts/check-conventions.mjs`.
- **`next-themes` and `@fontsource-variable/geist` removed** — both were installed by the shadcn template but unused; theme state comes from the ScaleLab settings store.
