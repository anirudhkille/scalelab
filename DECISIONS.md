# Decisions

One line each: decision, and why.

- **bun instead of pnpm** — the plan says pnpm, but the user chose bun and pnpm is not installed in this environment.
- **Node 26** — user requirement; `engines.node` is `>=26`.
- **oxlint instead of ESLint** — user requirement. oxlint cannot express `consistent-type-definitions` or feature import boundaries, so `scripts/check-conventions.mjs` enforces those rules alongside oxlint.
- **Vitest instead of an unspecified test runner** — user requirement; jsdom + Testing Library are configured.
- **React Router v8** — the plan allows React Router or TanStack; React Router is already installed and wired.
- **shadcn Base UI, preset `nova` / style `base-nova`** — matches the plan's Base UI requirement.
- **No `number-field` component** — it is not in the Base UI registry (CLI returned 404); the plan's fallback is `Input` plus a custom stepper when parameter forms arrive in M3.
- **Inter + JetBrains Mono** — chosen for UI/mono typography. `@fontsource-variable/geist` and `next-themes` remain installed but unused; remove them if they stay unused through M1.
- **Theme tokens live in `src/index.css`** — user requested that `theme.css` be folded into the Tailwind entry instead of a separate `shared/styles/theme.css`.
- **Lowercase kebab-case filenames** — user requirement. React component identifiers remain PascalCase.
- **`LoadStage` is defined in `features/challenges/schema.ts`** — challenges are to the left of simulation in the dependency graph, and simulation may import challenges. This avoids a forbidden challenges → simulation import.
- **`cn` from the official `cn` package** — generated by current shadcn/Base UI registry; `src/shared/lib/utils.ts` re-exports it for project code.
- **Challenges include an optional `referenceSolution`** — needed for the gated sample solution and engine tuning, even though the §5.2 schema snippet omits it.
- **`referenceSolution`/`starterArchitecture` are optional** — authored challenges can ship without either, and both are validated by `architectureSchema` when present.
- **Route screens live in `features/<name>/pages/`** — user requirement. `src/routes` is removed; the router imports page components from feature public APIs. The not-found fallback stays in `app/pages/` because it is app-level, not a domain feature.
